## Теоретическая часть

| Концепция | Описание |
|---|---|
| Алгоритм Дейкстры | Жадный алгоритм. На каждом шаге выбирает непосещённую вершину с минимальным расстоянием и релаксирует (обновляет) расстояния до её соседей. Использование `priority_queue` (двоичной кучи) позволяет извлекать минимум за O(log V). **Не работает с отрицательными весами.** |
| Алгоритм Флойда-Уоршелла | Алгоритм динамического программирования. Находит кратчайшие пути между *всеми* парами вершин. На каждой итерации `k` мы проверяем, можно ли сократить путь из `i` в `j`, пройдя через вершину `k`. **Работает с отрицательными весами** (если нет отрицательных циклов). Сложность — **O(V³)**. |
| Восстановление пути | Для Дейкстры используется массив предков `prev`. Для Флойда — матрица `next`, где `next[i][j]` хранит следующую вершину на пути от `i` к `j`. |

## Полный код решения

```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <climits>
#include <algorithm>
#include <locale.h>

using namespace std;

const int INF = INT_MAX;

class Graph {
    int V;
    vector<vector<int>> adj; // Матрица смежности (0 = нет ребра)

public:
    Graph(int v) : V(v), adj(v, vector<int>(v, 0)) {}

    // Для ориентированного графа добавляем только одно направление
    void addEdge(int u, int v, int w) { adj[u][v] = w; }

    // ==================== 1. АЛГОРИТМ ДЕЙКСТРЫ (Вариант 4) ====================
    void dijkstra(int start) {
        vector<int> dist(V, INF);
        vector<int> prev(V, -1);
        // Приоритетная очередь: пары (расстояние, вершина), по возрастанию
        priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> pq;

        dist[start] = 0;
        pq.push({0, start});

        while (!pq.empty()) {
            int d = pq.top().first;
            int u = pq.top().second;
            pq.pop();

            if (d > dist[u]) continue; // Устаревшая запись

            for (int v = 0; v < V; v++) {
                // Если ребро есть и мы можем улучшить расстояние
                if (adj[u][v] != 0 && dist[u] + adj[u][v] < dist[v]) {
                    dist[v] = dist[u] + adj[u][v];
                    prev[v] = u;
                    pq.push({dist[v], v});
                }
            }
        }

        // Вывод результатов
        cout << "=== Дейкстра (из вершины " << start << ") ===" << endl;
        for (int i = 0; i < V; i++) {
            if (dist[i] == INF) { cout << "До " << i << ": недостижима" << endl; continue; }
            cout << "До " << i << ": " << dist[i] << " (путь: ";
            vector<int> path;
            for (int v = i; v != -1; v = prev[v]) path.push_back(v);
            for (int j = path.size() - 1; j >= 0; j--) cout << path[j] << (j > 0 ? " -> " : "");
            cout << ")" << endl;
        }
    }

    // ==================== 2. АЛГОРИТМ ФЛОЙДА-УОРШЕЛЛА (Вариант 4) ====================
    void floydWarshall() {
        vector<vector<int>> dist(V, vector<int>(V, INF));
        vector<vector<int>> next(V, vector<int>(V, -1));

        // Инициализация
        for (int i = 0; i < V; i++) {
            dist[i][i] = 0;
            for (int j = 0; j < V; j++) {
                if (adj[i][j] != 0) {
                    dist[i][j] = adj[i][j];
                    next[i][j] = j; // Следующая вершина на пути
                }
            }
        }

        // Основной цикл (O(V^3))
        for (int k = 0; k < V; k++) {
            for (int i = 0; i < V; i++) {
                for (int j = 0; j < V; j++) {
                    if (dist[i][k] != INF && dist[k][j] != INF && dist[i][k] + dist[k][j] < dist[i][j]) {
                        dist[i][j] = dist[i][k] + dist[k][j];
                        next[i][j] = next[i][k];
                    }
                }
            }
        }

        // Вывод результатов
        cout << "\n=== Флойд-Уоршелл (все пары) ===" << endl;
        for (int i = 0; i < V; i++) {
            for (int j = 0; j < V; j++) {
                if (i == j || dist[i][j] == INF) continue;
                cout << i << " -> " << j << " (cost=" << dist[i][j] << "): ";
                int curr = i;
                cout << curr;
                while (curr != j) {
                    curr = next[curr][j];
                    cout << " -> " << curr;
                }
                cout << endl;
            }
        }
    }
};

// ==================== ГЛАВНАЯ ФУНКЦИЯ ====================
int main() {
    setlocale(LC_ALL, "ru");
    Graph g(5);

    // Создаем ОРИЕНТИРОВАННЫЙ граф
    g.addEdge(0, 1, 2);
    g.addEdge(0, 2, 5);
    g.addEdge(1, 2, 1);
    g.addEdge(1, 3, 6);
    g.addEdge(2, 3, 2);
    g.addEdge(2, 4, 3);
    g.addEdge(3, 4, 1);

    g.dijkstra(0);
    g.floydWarshall();

    return 0;
}
```

| **Дейкстра (с pq)** | **O((V + E) log V)** | O(V + E) | Нет | Массив `prev` |

## Преимущества и недостатки

**Алгоритм Дейкстры** — оптимален для поиска путей от *одной* вершины во взвешенном графе с неотрицательными весами, работает за O((V+E) log V) при использовании `priority_queue`. Основной недостаток — не работает с отрицательными весами, так как жадная стратегия «выбираем минимум» ломается. Для графов с отрицательными рёбрами (но без отрицательных циклов) применяют алгоритм Беллмана-Форда, работающий за O(V·E).

**Алгоритм Флойда-Уоршелла** — единственный из двух, кто находит пути сразу между *всеми* парами вершин и корректно работает с отрицательными весами (при отсутствии отрицательных циклов). Прост в реализации (три вложенных цикла) и позволяет легко восстанавливать пути через матрицу `next`. Основной недостаток — кубическая сложность O(V³) и O(V²) памяти: для графов с V > 5000 алгоритм становится неэффективным.

**Сравнение** — Дейкстра выигрывает по скорости для разреженных графов и задачи «из одной вершины», а Флойд-Уоршелл незаменим, когда нужны расстояния между всеми парами, либо в графах с отрицательными весами. На практике для разреженных графов с одной вершиной-источником всегда выбирают Дейкстру, а для плотных графов небольшого размера — Флойда.

## Контрольные вопросы

**1. Условия для Дейкстры:**
Все веса рёбер должны быть неотрицательными.

**2. Почему Дейкстра не работает с отрицательными весами?**
Он жадно выбирает минимальную вершину, считая, что до неё уже найден кратчайший путь. Отрицательное ребро может позже уменьшить этот путь, и алгоритм выдаст неверный результат.

**3. Сложность Дейкстры с приоритетной очередью:**
O((V+E) log V).

**4. Идея Флойда-Уоршелла:**
Динамическое программирование. Мы последовательно разрешаем использовать вершины `0, 1, ..., k` в качестве промежуточных для всех пар `(i, j)`.

**5. Сложность Флойда-Уоршелла:**
O(V³) из-за трёх вложенных циклов.

**6. Обнаружение отрицательных циклов:**
После работы алгоритма, если на главной диагонали матрицы расстояний `dist[i][i] < 0`, значит, существует отрицательный цикл.

**7. Когда лучше Дейкстра?**
Для поиска путей от *одной* вершины в графах с неотрицательными весами (быстрее, чем Флойд).

**8. Когда лучше Флойд?**
Когда нужны пути между *всеми* парами вершин или если в графе есть отрицательные веса (но нет циклов).

**9. Восстановление пути в Дейкстре:**
Хранить массив `prev`, где `prev[v]` — предок `v`. Восстанавливать путь в обратном порядке от конца к началу.

**10. Восстановление пути в Флойде:**
Хранить матрицу `next`, где `next[i][j]` — следующая вершина после `i` на пути к `j`. Идти по ней, пока не достигнем `j`.

**11. Релаксация:**
Процесс обновления расстояния до вершины, если найден более короткий путь (`if (dist[u] + w < dist[v]) dist[v] = dist[u] + w`).

**12. Оптимизация Дейкстры для разреженных графов:**
Использовать список смежности и `priority_queue` (двоичную кучу) или кучу Фибоначчи.

**13. Память для Флойда:**
Требует O(V²) памяти для хранения матрицы смежности (или расстояний).

**14. Когда Флойд неприменим?**
На очень больших графах (например, V > 5000), так как O(V³) работает слишком медленно, а O(V²) памяти может не хватить.

**15. Второй кратчайший путь (Дейкстра):**
Нужно хранить два расстояния для каждой вершины (кратчайшее и второе кратчайшее) и обновлять их при релаксации.
