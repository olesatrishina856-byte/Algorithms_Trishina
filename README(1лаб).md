## Теоретическая часть

| Концепция | Описание | Реализация в C++ |
|---|---|---|
| Композиция | Сильная связь «часть-целое». Часть создаётся и уничтожается вместе с целым. | Поля-объекты (значения) или `std::unique_ptr` |
| Агрегация | Слабая связь «часть-целое». Часть может существовать независимо от целого. | Указатели или ссылки |
| Статические члены | Принадлежат классу, а не объекту. Используются для общих данных. | `static` в классе, определение вне класса |
| Паттерн «Одиночка» | Гарантирует наличие единственного экземпляра класса и глобальную точку доступа. | Приватный конструктор, статический метод `getInstance()` |

## Полный код решения

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <memory> // для std::unique_ptr и std::make_unique
#include <locale.h>

using namespace std;

// КЛАСС DISH
class Dish {
private:
    string name;
    double price;
public:
    static int dishCount; // статический счётчик всех созданных блюд

    Dish(const string& n, double p) : name(n), price(p) {
        dishCount++;
        cout << " [Создано блюдо]: " << name << " (" << price << " pyб.)" << endl;
    }

    ~Dish() {
        dishCount--;
        cout << " [Удалено блюдо]: " << name << endl;
    }

    // Запрещаем копирование и присваивание,
    // чтобы счётчик не сбивался при перевыделении памяти
    Dish(const Dish&) = delete;
    Dish& operator=(const Dish&) = delete;

    void print() const {
        cout << " - " << name << " - " << price << " pyб." << endl;
    }
};

// Определение статического поля вне класса
int Dish::dishCount = 0;


// КЛАСС ORDER
class Order {
private:
    int orderId;
    // композиция через unique_ptr:
    // блюда принадлежат только этому заказу и умирают вместе с ним.
    // unique_ptr не копируется, поэтому счётчик Dish не сбивается.
    vector<unique_ptr<Dish>> dishes;

public:
    Order(int id) : orderId(id) {
        cout << "Создан заказ №" << orderId << endl;
    }

    ~Order() {
        // vector<unique_ptr> сам корректно удалит все Dish
        cout << "Удален заказ №" << orderId << " (вместе со всеми блюдами)" << endl;
    }

    // Добавление блюда (создание части внутри целого)
    void addDish(const string& name, double price) {
        dishes.push_back(make_unique<Dish>(name, price));
    }

    void print() const {
        cout << " Заказ №" << orderId << ":" << endl;
        if (dishes.empty()) {
            cout << "   (пусто)" << endl;
        }
        else {
            for (const auto& dish : dishes) {
                dish->print();
            }
        }
    }

    int getId() const { return orderId; }
};


// КЛАСС RESTAURANT
class Restaurant {
private:
    static Restaurant* instance; // статический указатель на единственный экземпляр
    string name;
    vector<Order*> orders; // АГРЕГАЦИЯ: заказы существуют независимо от ресторана

    // Приватный конструктор – нельзя создать объект извне
    Restaurant(const string& n) : name(n) {
        cout << "Ресторан \"" << name << "\" открыт." << endl;
    }

public:
    // Запрет копирования (одиночка не должен копироваться)
    Restaurant(const Restaurant&) = delete;
    Restaurant& operator=(const Restaurant&) = delete;

    // Статический метод получения единственного экземпляра
    static Restaurant* getInstance(const string& n = "Гурман") {
        if (instance == nullptr) {
            instance = new Restaurant(n);
        }
        return instance;
    }

    // Статический метод корректного уничтожения одиночки
    static void destroyInstance() {
        if (instance != nullptr) {
            delete instance;
            instance = nullptr;
            cout << "Экземпляр ресторана успешно уничтожен." << endl;
        }
    }

    // Деструктор
    ~Restaurant() {
        cout << "Ресторан \"" << name << "\" закрыт." << endl;
        // ВАЖНО: заказы НЕ удаляем – они агрегируются, а не компонуются!
    }

    // Добавление заказа в ресторан (агрегация)
    void addOrder(Order* order) {
        orders.push_back(order);
        cout << "Заказ \"" << order->getId()
            << " принят в ресторан \"" << name << "\"." << endl;
    }

    // Вывод всех заказов
    void printAllOrders() const {
        cout << "\n=== Список заказов в ресторане \"" << name << "\" ===" << endl;
        if (orders.empty()) {
            cout << " Нет активных заказов." << endl;
        }
        else {
            for (const auto* order : orders) {
                order->print();
            }
        }
        cout << "=========================================" << endl;
    }
};

// Определение статического поля класса Restaurant
Restaurant* Restaurant::instance = nullptr;


int main() {
    setlocale(LC_ALL, "ru");

    cout << "--- Демонстрация паттерна Одиночка ---" << endl;
    Restaurant* rest1 = Restaurant::getInstance("Вкусно и точка");
    Restaurant* rest2 = Restaurant::getInstance("Другое название"); // вернёт тот же объект

    if (rest1 == rest2) {
        cout << ">>> Успех: rest1 и rest2 указывают на один и тот же объект (Singleton)." << endl;
    }

    cout << "\n--- Создание заказов (Агрегация) ---" << endl;
    // Заказы создаются независимо от ресторана
    Order* order1 = new Order(101);
    Order* order2 = new Order(102);

    cout << "\n--- Добавление блюд (Композиция) ---" << endl;
    // Блюда создаются внутри заказов
    order1->addDish("Стейк Рибай", 2500.0);
    order1->addDish("Красное вино", 800.0);

    order2->addDish("Паста Карбонара", 1200.0);
    order2->addDish("Тирамису", 600.0);
    order2->addDish("Эспрессо", 300.0);

    cout << "\n--- Добавление заказов в ресторан (Агрегация) ---" << endl;
    rest1->addOrder(order1);
    rest1->addOrder(order2);

    rest1->printAllOrders();

    cout << "\n--- Проверка статического счётчика ---" << endl;
    cout << "Всего блюд создано (Dish::dishCount): " << Dish::dishCount << endl;

    cout << "\n--- Демонстрация времени жизни: Удаляем заказы ---" << endl;
    cout << "Удаляем order1 и order2 (они умирают, а вместе с ними и их блюда): " << endl;
    delete order1;
    delete order2;

    cout << "\nПосле удаления заказов (блюда уничтожены, но ресторан жив): " << endl;
    cout << "Текущее количество блюд (Dish::dishCount): " << Dish::dishCount << endl;
    cout << "Ресторан продолжает работать, хотя заказы уже удалены." << endl;

    cout << "\n--- Завершение работы программы ---" << endl;
    // Уничтожаем Одиночку через специальный статический метод
    Restaurant::destroyInstance();

    return 0;
}
```

## Результаты и выводы
Реализована сильная связь (композиция) между Order и Dish с использованием std::unique_ptr.

Реализована слабая связь (агрегация) между Restaurant и Order с использованием сырых указателей.

Освоен паттерн «Одиночка» для класса Restaurant с корректным освобождением памяти.

Продемонстрирован статический счётчик Dish::dishCount, который корректно уменьшается при удалении заказов.

Показано, что при удалении заказов (целых) их блюда (части) уничтожаются, а ресторан (агрегатор) продолжает работать.

## Преимущества и недостатки
Композиция: строгое владение, отсутствие утечек памяти, но части нельзя использовать отдельно. Идеально для Order и Dish.

Агрегация: гибкость, заказы могут существовать независимо, но требуется ручное управление памятью. Подходит для Restaurant и Order.

Одиночка (Singleton): контролируемый доступ к глобальному ресурсу, но может усложнить тестирование и создать скрытые зависимости.

**Контрольные вопросы**
1.Что такое композиция?
Это отношение «часть-целое», при котором часть не может существовать без целого. Пример: Дом и Комнаты.

2.Что такое агрегация? Чем она отличается от композиции?
Это отношение «часть-целое», где часть может существовать независимо от целого. Отличие: при агрегации часть может жить дольше целого и принадлежать нескольким целым.

3.Как реализовать композицию в С++? Приведите пример кода.
Через поля-объекты (значения) или std::unique_ptr. Пример: class Order { vector<Dish> dishes; };.

4.Как реализовать агрегацию в С++? Приведите пример кода.
Через указатели или ссылки. Пример: class Restaurant { vector<Order*> orders; };.

5.В чём разница между временем жизни частей при композиции и агрегации?
При композиции часть умирает строго вместе с целым. При агрегации часть может жить после уничтожения целого.

6.Что такое статическое поле класса? Чем оно отличается от обычного поля?
Это поле, принадлежащее всему классу, а не конкретному объекту. Оно существует в единственном экземпляре и общее для всех объектов.

7.Как объявить и определить статическое поле? Где оно хранится?
Объявляется в классе со словом static, определяется вне класса (инициализируется). Хранится в статической области памяти.

8.Что такое статический метод? Можно ли из него обратиться к нестатическим полям?
Метод, вызываемый без создания объекта. Нет, нельзя, так как у него нет указателя this.

9.Для чего используются статические счётчики объектов?
Для подсчёта количества созданных или существующих в данный момент объектов класса.

10.Что такое паттерн «Одиночка» (Singleton)? Для чего он нужен?
Паттерн, гарантирующий наличие единственного экземпляра класса. Нужен для управления глобальными ресурсами (например, настройками, подключением к БД).

11.Как запретить создание копий объекта (конструктор копирования)?
Удалить конструктор копирования и оператор присваивания: Class(const Class&) = delete;.

12.В каком порядке вызываются конструкторы и деструкторы при композиции?
Конструкторы: сначала части, затем целое. Деструкторы: сначала целое, затем части.

13.Можно ли изменить статическое поле из обычного метода?
Да, если оно не объявлено как const.

14.Почему статические поля нужно определять вне класса?
Потому что объявление внутри класса — это лишь указание компилятору, а память под них выделяется только при определении вне класса.

15.В каких случаях стоит использовать композицию, а в каких - агрегацию?
Композиция — когда часть не имеет смысла без целого (Дом-Комната). Агрегация — когда часть может быть общей или существовать отдельно (Библиотека-Книга).
