## Теоретическая часть

| Алгоритм | Описание |
|---|---|
| Быстрая сортировка (Quick Sort) | Алгоритм «разделяй и властвуй». Выбирается опорный элемент (pivot), массив разделяется на две части: меньше и больше опорного. Сложность в среднем O(n log n), в худшем O(n²). Дополнительная память O(log n), не устойчива. |
| Сортировка слиянием (Merge Sort) | Делит массив пополам, рекурсивно сортирует каждую половину и сливает их. Всегда работает за O(n log n), требует O(n) дополнительной памяти. Устойчива. |
| Пирамидальная сортировка (Heap Sort) | Использует структуру данных «двоичная куча» (max-heap). Строим кучу, затем извлекаем максимумы. Работает за O(n log n), не требует доп. памяти O(1), не устойчива. |
| Stream API в C++ | Механизм работы с потоками данных. Итераторы `std::istream_iterator` позволяют читать данные из потока (например, файла или `std::cin`) как из обычного контейнера, а `std::ostream_iterator` — записывать данные в поток (например, `std::cout` или файл). |

## Полный код решения

```cpp
#include <iostream>
#include <vector>
#include <fstream>
#include <sstream>
#include <iterator>  // для istream_iterator, ostream_iterator
#include <algorithm> // для std::copy
#include <chrono>
#include <locale.h>

using namespace std;
using namespace chrono;

// ==================== 1. БЫСТРАЯ СОРТИРОВКА ====================
int partition(vector<int>& arr, int low, int high) {
    int pivot = arr[high]; // Опорный элемент - последний
    int i = low - 1;
    for (int j = low; j < high; j++) {
        if (arr[j] <= pivot) {
            i++;
            swap(arr[i], arr[j]);
        }
    }
    swap(arr[i + 1], arr[high]);
    return i + 1;
}

void quickSort(vector<int>& arr, int low, int high) {
    if (low < high) {
        int pi = partition(arr, low, high);
        quickSort(arr, low, pi - 1);
        quickSort(arr, pi + 1, high);
    }
}

// ==================== 2. ПИРАМИДАЛЬНАЯ СОРТИРОВКА ====================
void heapify(vector<int>& arr, int n, int i) {
    int largest = i;
    int left = 2 * i + 1;
    int right = 2 * i + 2;

    if (left < n && arr[left] > arr[largest]) largest = left;
    if (right < n && arr[right] > arr[largest]) largest = right;

    if (largest != i) {
        swap(arr[i], arr[largest]);
        heapify(arr, n, largest);
    }
}

void heapSort(vector<int>& arr) {
    int n = arr.size();
    // Построение кучи
    for (int i = n / 2 - 1; i >= 0; i--) heapify(arr, n, i);
    // Извлечение элементов
    for (int i = n - 1; i > 0; i--) {
        swap(arr[0], arr[i]);
        heapify(arr, i, 0);
    }
}

// ==================== 3. СОРТИРОВКА СЛИЯНИЕМ (ДЛЯ STREAM API) ====================
void merge(vector<int>& arr, int left, int mid, int right) {
    vector<int> temp(right - left + 1);
    int i = left, j = mid + 1, k = 0;

    while (i <= mid && j <= right) {
        temp[k++] = (arr[i] <= arr[j]) ? arr[i++] : arr[j++];
    }
    while (i <= mid) temp[k++] = arr[i++];
    while (j <= right) temp[k++] = arr[j++];

    for (int idx = 0; idx < k; idx++) arr[left + idx] = temp[idx];
}

void mergeSort(vector<int>& arr, int left, int right) {
    if (left < right) {
        int mid = left + (right - left) / 2;
        mergeSort(arr, left, mid);
        mergeSort(arr, mid + 1, right);
        merge(arr, left, mid, right);
    }
}

// ==================== ГЛАВНАЯ ФУНКЦИЯ ====================
int main() {
    setlocale(LC_ALL, "ru");

    // --- 1. Демонстрация Stream API для сортировки слиянием ---
    cout << "=== 1. Merge Sort для Stream API ===" << endl;

    // Создаем строковый поток с исходными данными
    stringstream inputStream("64 34 25 12 22 11 90 5");
    vector<int> streamData;

    // Читаем данные из потока с помощью istream_iterator
    istream_iterator<int> start(inputStream), end;
    copy(start, end, back_inserter(streamData));

    cout << "Исходные данные из потока: ";
    copy(streamData.begin(), streamData.end(), ostream_iterator<int>(cout, " "));
    cout << endl;

    // Сортируем
    mergeSort(streamData, 0, streamData.size() - 1);

    // Выводим в выходной поток с помощью ostream_iterator
    cout << "Отсортированные данные (в поток): ";
    copy(streamData.begin(), streamData.end(), ostream_iterator<int>(cout, " "));
    cout << endl << endl;


    // --- 2. Сравнение производительности ---
    cout << "=== 2. Сравнение производительности алгоритмов ===" << endl;

    const int N = 50000;
    vector<int> original(N);
    for (int i = 0; i < N; i++) original[i] = rand() % N;

    auto testSort = [&](string name, auto sortFunc) {
        vector<int> copy = original;
        auto startT = high_resolution_clock::now();
        sortFunc(copy);
        auto endT = high_resolution_clock::now();
        auto time = duration_cast<microseconds>(endT - startT).count();
        cout << name << ": " << time << " мкс" << endl;
    };

    testSort("Быстрая сортировка", [](vector<int>& v) { quickSort(v, 0, v.size() - 1); });
    testSort("Сортировка слиянием", [](vector<int>& v) { mergeSort(v, 0, v.size() - 1); });
    testSort("Пирамидальная сортировка", [](vector<int>& v) { heapSort(v); });

    return 0;
}
```

## Преимущества и недостатки

**Quick Sort** — самый быстрый на практике благодаря хорошей локальности кэша и работе «на месте», но имеет риск деградации до O(n²) при неудачном выборе опорного элемента и не устойчив.

**Merge Sort** — гарантирует O(n log n) в любом случае и устойчив, но требует O(n) дополнительной памяти и на практике проигрывает Quick Sort из-за постоянных аллокаций временных массивов.

**Heap Sort** — единственный из трёх, кто даёт одновременно гарантированное O(n log n) и O(1) дополнительной памяти, что делает его оптимальным для встраиваемых систем, но на практике он медленнее остальных из-за плохой локальности кэша.

## Контрольные вопросы

**1. Какова сложность быстрой сортировки в лучшем, среднем и худшем случае?**
Лучший и средний: O(n log n). Худший: O(n²).

**2. Когда возникает худший случай для быстрой сортировки?**
Когда опорный элемент выбирается неудачно (например, всегда минимальный или максимальный). Это происходит, если массив уже отсортирован, а опорным выбирается первый или последний элемент.

**3. Как можно улучшить быструю сортировку для защиты от худшего случая?**
Использовать случайный выбор опорного элемента (Randomized QuickSort) или выбирать медиану из трёх (первый, средний, последний элементы).

**4. Какова сложность сортировки слиянием? Почему она всегда O(n log n)?**
O(n log n). Алгоритм всегда делит массив пополам (глубина рекурсии log n), и на каждом уровне происходит слияние, требующее O(n) операций. Итог: O(n) · O(log n) = O(n log n).

**5. Какие преимущества и недостатки имеет сортировка слиянием перед быстрой?**
Преимущества: гарантированное время O(n log n) и устойчивость. Недостатки: требует O(n) дополнительной памяти, в то время как QuickSort работает на месте (O(log n) на стек).

**6. Как работает пирамидальная сортировка? Какова её сложность?**
Строится max-куча. Затем корень (максимум) меняется с последним элементом, размер кучи уменьшается, и свойство кучи восстанавливается (`heapify`). Сложность O(n log n).

**7. Какая из трёх сортировок устойчивая? Почему?**
Только сортировка слиянием. При слиянии, если элементы равны, мы сначала берём элемент из левой половины, сохраняя их исходный относительный порядок.

**8. Какая из трёх сортировок требует дополнительной памяти? Сколько?**
Сортировка слиянием. Требует O(n) памяти для временного массива при слиянии. QuickSort требует O(log n) для стека вызовов.

**9. Какая из трёх сортировок лучше работает на почти отсортированных данных?**
Быстрая сортировка (если выбран хороший опорный элемент) или сортировка вставками (не из этого списка). Пирамидальная и слиянием не получают преимуществ от частичной отсортированности.

**10. Зачем в пирамидальной сортировке сначала строится куча?**
Чтобы получить максимальный элемент в корне за O(1) и иметь возможность эффективно извлекать следующие максимумы.

**11. Что такое «разделяй и властвуй»? Как он применяется в быстрой сортировке и сортировке слиянием?**
Это стратегия, при которой задача разбивается на подзадачи меньшего размера, которые решаются независимо, а затем их результаты объединяются. В QuickSort мы делим массив относительно pivot, в MergeSort — пополам.

**12. Можно ли реализовать быструю сортировку итеративно (без рекурсии)?**
Да, используя явный стек (например, `std::stack`) для хранения границ подмассивов (`low` и `high`).

**13. Почему быстрая сортировка обычно быстрее сортировки слиянием на практике?**
Из-за лучшей локальности кэша (работает в пределах одного массива) и меньших накладных расходов на выделение памяти (MergeSort постоянно создаёт временные массивы).

**14. Когда выгодно использовать пирамидальную сортировку?**
Когда требуется гарантированное время O(n log n) и строго ограниченная память O(1) (например, во встраиваемых системах).

**15. Какой алгоритм сортировки вы бы выбрали для встроенных систем с ограниченной памятью?**
Пирамидальную сортировку (Heap Sort), так как она не требует дополнительной памяти O(n) и не уходит в глубокую рекурсию, как QuickSort.
