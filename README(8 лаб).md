## Теоретическая часть

| Концепция | Описание |
|---|---|
| Хеш-таблица | Структура данных, реализующая ассоциативный массив. Использует хеш-функцию для преобразования ключа в индекс массива, что позволяет выполнять поиск, вставку и удаление в среднем за **O(1)**. |
| Коллизия | Ситуация, когда два разных ключа дают одинаковый хеш-индекс. |
| Открытая адресация | Метод разрешения коллизий, при котором все элементы хранятся непосредственно в массиве. Если ячейка занята, ищем следующую свободную по определённому правилу (пробирование). |
| Двойное хеширование | Метод открытой адресации, при котором шаг пробирования вычисляется с помощью **второй хеш-функции**. Формула: `index = (hash1(key) + i * hash2(key)) % size`, где `i` — номер попытки. Позволяет избежать «первичной кластеризации». Главное правило: `hash2(key)` не должна возвращать 0. |
| Надгробия (Tombstones) | Метки удалённых элементов. При открытой адресации нельзя просто стереть элемент (это разорвёт цепочку поиска), поэтому ячейку помечают как «удалённую», и в неё можно вставлять новые элементы. |

## Полный код решения

```cpp
#include <iostream>
#include <vector>
#include <locale.h>

using namespace std;

class HashTable {
private:
    int size, count;
    vector<int> keys, values;
    vector<int> status; // 0-пусто, 1-занято, 2-удалено (надгробие)

    // Две хеш-функции для двойного хеширования
    int hash1(int k) const { return k % size; }
    int hash2(int k) const { return 1 + (k % (size - 1)); } // Шаг всегда > 0

public:
    HashTable(int s = 13) : size(s), count(0) {
        keys.resize(size);
        values.resize(size);
        status.assign(size, 0); // Изначально всё пусто
    }

    // Вставка (с обработкой коллизий и переиспользованием удалённых ячеек)
    void insert(int k, int v) {
        int idx = hash1(k), step = hash2(k), firstDel = -1;

        for (int i = 0; i < size; i++) {
            int curr = (idx + i * step) % size;

            if (status[curr] == 1 && keys[curr] == k) {
                values[curr] = v; return; // Ключ уже есть — обновляем значение
            }
            if (status[curr] == 2 && firstDel == -1) firstDel = curr; // Запомнили удалённую ячейку
            if (status[curr] == 0) {
                // Нашли пустую: вставляем туда или в ранее найденную удалённую
                int target = (firstDel != -1) ? firstDel : curr;
                keys[target] = k; values[target] = v; status[target] = 1; count++;
                return;
            }
        }
        // Если дошли до конца, но была удалённая ячейка
        if (firstDel != -1) {
            keys[firstDel] = k; values[firstDel] = v; status[firstDel] = 1; count++;
        }
    }

    // Поиск
    bool find(int k, int& res) const {
        int idx = hash1(k), step = hash2(k);
        for (int i = 0; i < size; i++) {
            int curr = (idx + i * step) % size;
            if (status[curr] == 0) return false; // Пустая ячейка — значит ключа нет
            if (status[curr] == 1 && keys[curr] == k) { res = values[curr]; return true; }
        }
        return false;
    }

    // Удаление
    bool remove(int k) {
        int idx = hash1(k), step = hash2(k);
        for (int i = 0; i < size; i++) {
            int curr = (idx + i * step) % size;
            if (status[curr] == 0) return false;
            if (status[curr] == 1 && keys[curr] == k) {
                status[curr] = 2; count--; return true; // Ставим метку "удалено"
            }
        }
        return false;
    }

    // Красивый вывод таблицы
    void print() const {
        cout << "Хеш-таблица:" << endl;
        for (int i = 0; i < size; i++) {
            cout << i << ": ";
            if (status[i] == 1) cout << "[" << keys[i] << " : " << values[i] << "]";
            else if (status[i] == 2) cout << "<удалено>";
            else cout << "<пусто>";
            cout << endl;
        }
    }
};

int main() {
    setlocale(LC_ALL, "ru");
    HashTable ht(7); // Размер 7 (простое число)

    // Демонстрация (вызываем коллизии)
    ht.insert(10, 100);
    ht.insert(17, 170); // 17 % 7 = 3 (коллизия с 10)
    ht.insert(24, 240); // 24 % 7 = 3 (ещё одна коллизия)

    ht.print();

    int val;
    cout << "\nПоиск 24: " << (ht.find(24, val) ? to_string(val) : "не найден") << endl;

    ht.remove(17);
    cout << "\nПосле удаления 17:" << endl;
    ht.print();

    return 0;
}
```

## Анализ сложности реализованных операций

| Операция | Средний случай | Худший случай | Обоснование |
|---|---|---|---|
| `insert` | **O(1)** | **O(n)** | В среднем коллизий мало, и место находится за пару шагов. В худшем (все ключи дают одинаковый хеш) придётся пройти весь массив. |
| `find` | **O(1)** | **O(n)** | Поиск идёт до первого совпадения или пустой ячейки. |
| `remove` | **O(1)** | **O(n)** | Поиск элемента для удаления занимает в среднем O(1). |

Мы убедились, что двойное хеширование решает проблему кластеризации, характерную для линейного пробирования, за счёт использования второй хеш-функции для вычисления шага. Также была освоена работа с «надгробиями» (tombstones) — метками удалённых элементов, которые необходимы, чтобы не разрывать цепочку поиска при открытой адресации.

## Преимущества и недостатки

**Двойное хеширование** — обеспечивает равномерное распределение элементов и минимальное число коллизий, близкое к идеальному (по сравнению с линейным и квадратичным пробированием). Основной недостаток — вычисление второй хеш-функции требует дополнительного времени, а также необходимость хранения «надгробий», которые со временем накапливаются и требуют периодического рехеширования.

**Метод цепочек** — проще в реализации, не требует надгробий, легко удаляет элементы, но расходует дополнительную память на узлы списков и хуже работает с кэшем.

**Хеш-таблица в целом** — обеспечивает O(1) в среднем, но проигрывает двоичному поиску по памяти и не даёт упорядоченного обхода; при большом коэффициенте загрузки (> 0.7) производительность резко падает без рехеширования.

## Контрольные вопросы

**1. Что такое хеш-таблица? Из каких компонентов она состоит?**
Это структура данных для хранения пар «ключ-значение». Состоит из массива (бакетов), хеш-функции и механизма разрешения коллизий.

**2. Какие требования предъявляются к хеш-функции?**
Детерминированность (один ключ — один хеш), быстрота вычисления, равномерное распределение (минимизация коллизий).

**3. Что такое коллизия в хеш-таблице? Как с ней бороться?**
Ситуация, когда два разных ключа вычисляют одинаковый индекс. Борются методом цепочек (связные списки) или открытой адресацией (поиск другой ячейки).

**4. В чём отличие метода цепочек от открытой адресации?**
При методе цепочек элементы с одинаковым хешем хранятся в виде списка вне основного массива. При открытой адресации все элементы хранятся строго внутри массива, и мы ищем следующую свободную ячейку.

**5. Что такое первичная и вторичная кластеризация?**
Первичная — при линейном пробировании элементы слипаются в длинные блоки. Вторичная — при квадратичном пробировании, менее выражена. Двойное хеширование устраняет кластеризацию.

**6. Какова средняя и худшая сложность операций в хеш-таблице?**
Средняя: **O(1)**. Худшая: **O(n)** (если все элементы попали в одну коллизию).

**7. Когда эффективнее использовать двоичный поиск, а когда — хеш-таблицу?**
Бинарный поиск лучше, если данные статичны (редко меняются) и уже отсортированы. Хеш-таблица лучше для динамических данных с частыми вставками/удалениями.

**8. Что такое коэффициент загрузки хеш-таблицы? Почему он важен?**
Отношение количества элементов к размеру таблицы (`count / size`). Если он приближается к 1, производительность падает. При коэффициенте > 0.7 обычно делают рехеширование.

**9. Как работает рехеширование (динамическое расширение)?**
Создаётся новый массив большего размера (обычно в 2 раза), и все старые элементы заново вставляются в него с пересчётом хешей.

**10. Как выбрать размер хеш-таблицы? Почему часто выбирают простое число?**
Размер выбирают простым числом, чтобы хеш-функция `key % size` распределяла элементы более равномерно и уменьшала количество коллизий.

**11. Как реализовать хеш-функцию для строк?**
Можно брать код каждого символа, умножать на простое число (например, 31) и складывать: `hash = hash * 31 + char`.
