## Теоретическая часть

| Концепция | Описание |
|---|---|
| Наследование | Механизм создания новых классов на основе существующих (отношение «is a»). |
| Полиморфизм (позднее связывание) | Способность объектов с одинаковым интерфейсом (базовым классом) иметь разную реализацию. Реализуется через виртуальные методы (`virtual`). |
| Абстрактный класс | Класс, содержащий хотя бы один чисто виртуальный метод (`= 0`). От него нельзя создать объект, он служит только для наследования. |
| Виртуальный деструктор | Гарантирует, что при удалении объекта через указатель на базовый класс вызовутся деструкторы всех производных классов (важно для предотвращения утечек памяти). |
| Сериализация | Процесс сохранения состояния объектов (в данном случае в текстовый файл). |

## Полный код решения

```cpp
#include <iostream>
#include <vector>
#include <memory>
#include <fstream>
#include <string>
#include <iomanip>
#include <locale.h>

using namespace std;

// ==================== 1. БАЗОВЫЙ АБСТРАКТНЫЙ КЛАСС ====================
class Employee {
protected:
    int id;
    string name;
public:
    Employee(int i, const string& n) : id(i), name(n) {}
    virtual ~Employee() = default; // Виртуальный деструктор!

    virtual double getSalary() const = 0; // Чисто виртуальный
    virtual string getType() const = 0;   // Чисто виртуальный

    virtual void print() const {
        cout << setw(3) << id << " | " << setw(15) << left << name
             << " | " << setw(10) << getType() << " | ЗП: " << getSalary() << " руб." << endl;
    }
    int getId() const { return id; }
    string getName() const { return name; }
};

// ==================== 2. ПРОИЗВОДНЫЕ КЛАССЫ ====================
class Manager : public Employee {
    double base, bonus;
public:
    Manager(int i, const string& n, double b, double bo) : Employee(i, n), base(b), bonus(bo) {}
    double getSalary() const override { return base + bonus; }
    string getType() const override { return "Manager"; }
    double getBase() const { return base; }
    double getBonus() const { return bonus; }
};

class Developer : public Employee {
    double rate; int hours;
public:
    Developer(int i, const string& n, double r, int h) : Employee(i, n), rate(r), hours(h) {}
    double getSalary() const override { return rate * hours; }
    string getType() const override { return "Developer"; }
    double getRate() const { return rate; }
    int getHours() const { return hours; }
};

// ==================== 3. СИСТЕМА УПРАВЛЕНИЯ ====================
class HRSystem {
    vector<unique_ptr<Employee>> staff;
public:
    void add(unique_ptr<Employee> emp) { staff.push_back(move(emp)); }

    void showReport() const {
        cout << "\n--- ОТЧЁТ ПО ПЕРСОНАЛУ ---" << endl;
        double total = 0;
        for (const auto& e : staff) {
            e->print();
            total += e->getSalary();
        }
        cout << "--------------------------" << endl;
        cout << "ИТОГО ФОНД ОПЛАТЫ ТРУДА: " << total << " руб." << endl;
    }

    // Сериализация (Сохранение)
    void saveToFile(const string& filename) const {
        ofstream out(filename);
        for (const auto& e : staff) {
            out << e->getType() << " " << e->getId() << " " << e->getName() << " ";
            if (e->getType() == "Manager") {
                auto* m = dynamic_cast<Manager*>(e.get());
                out << m->getBase() << " " << m->getBonus();
            } else if (e->getType() == "Developer") {
                auto* d = dynamic_cast<Developer*>(e.get());
                out << d->getRate() << " " << d->getHours();
            }
            out << "\n";
        }
        cout << "Данные сохранены в " << filename << endl;
    }

    // Десериализация (Загрузка)
    void loadFromFile(const string& filename) {
        ifstream in(filename);
        if (!in) { cout << "Файл не найден!\n"; return; }
        staff.clear();
        string type, name; int id; double p1, p2;
        while (in >> type >> id >> name >> p1 >> p2) {
            if (type == "Manager") add(make_unique<Manager>(id, name, p1, p2));
            else if (type == "Developer") add(make_unique<Developer>(id, name, p1, (int)p2));
        }
        cout << "Данные загружены из " << filename << endl;
    }
};

// ==================== ГЛАВНАЯ ФУНКЦИЯ ====================
int main() {
    setlocale(LC_ALL, "ru");
    HRSystem hr;
    string file = "staff.txt";
    int choice;

    do {
        cout << "\n=== СИСТЕМА УПРАВЛЕНИЯ ПЕРСОНАЛОМ ===" << endl;
        cout << "1. Добавить менеджера\n2. Добавить разработчика\n3. Показать отчёт\n4. Сохранить\n5. Загрузить\n0. Выход\nВыбор: ";
        cin >> choice;

        if (choice == 1) {
            int id; string name; double base, bonus;
            cout << "ID, Имя, Оклад, Бонус: "; cin >> id >> name >> base >> bonus;
            hr.add(make_unique<Manager>(id, name, base, bonus));
        }
        else if (choice == 2) {
            int id; string name; double rate; int hours;
            cout << "ID, Имя, Ставка (руб/час), Часы: "; cin >> id >> name >> rate >> hours;
            hr.add(make_unique<Developer>(id, name, rate, hours));
        }
        else if (choice == 3) hr.showReport();
        else if (choice == 4) hr.saveToFile(file);
        else if (choice == 5) hr.loadFromFile(file);
    } while (choice != 0);

    return 0;
}
```

## Анализ архитектуры и сложности

| Операция | Сложность | Обоснование |
|---|---|---|
| **Добавление сотрудника** | **O(1)** амортизированно | `push_back` в `vector` + перемещение `unique_ptr`. |
| **Показ отчёта** | **O(N)** | Один проход по всем сотрудникам, полиморфный вызов `getSalary()` через vtable. |
| **Сохранение в файл** | **O(N)** | Один проход по контейнеру + запись в `ofstream`. |
| **Загрузка из файла** | **O(N)** | Построчное чтение + `make_unique` для каждого сотрудника. |
| **Поиск по ID** | **O(N)** | В данной реализации не оптимизирован; для ускорения можно использовать `std::unordered_map<int, Employee*>`. |

## Преимущества и недостатки

**Наследование и полиморфизм** — делают код расширяемым: чтобы добавить новый тип сотрудника (например, `Intern` или `Freelancer`), достаточно унаследоваться от `Employee` и реализовать `getSalary()` и `getType()`, не меняя `HRSystem`. Это яркий пример принципа открытости/закрытости (OCP). Основной недостаток — виртуальные вызовы дороже обычных (обращение к vtable), а также возрастает сложность отладки из-за позднего связывания.

**`unique_ptr` вместо сырых указателей** — гарантирует автоматическое освобождение памяти (RAII), исключает утечки даже при исключениях, а `std::move` при передаче в контейнер делает владение явным. Недостаток — нельзя копировать `unique_ptr`, что требует аккуратной работы с перемещением (в частности, в `loadFromFile` приходится каждый раз создавать новый объект).

**Виртуальный деструктор** — критически важен при хранении объектов по указателю на базовый класс: без него `delete basePtr` не вызвал бы деструктор производного класса и привёл к утечке (или UB). Это правило «если в классе есть хотя бы один виртуальный метод — деструктор тоже должен быть виртуальным».

**Сериализация в текстовый файл** — проста и читаема человеком, легко отлаживается. Недостаток — медленнее и объёмнее бинарных форматов (protobuf, JSON с парсером), а также нет обработки ошибок при повреждённом файле (в реальной системе стоило бы добавить проверки и версионирование формата).

**`dynamic_cast` для сериализации** — приемлем в учебной задаче, но в идеале каждая реализация должна сама уметь себя сериализовать (виртуальный `serialize()`/`deserialize()`), что соответствует принципу полиморфизма. Это позволило бы избежать `dynamic_cast` и сделать код более расширяемым.

## Контрольные вопросы

**1. Что такое наследование? Виды в C++?**
Механизм создания нового класса на базе существующего. Виды: `public` (is-a), `protected`, `private`.

**2. Что такое открытое наследование?**
Отношение «является» (is-a). Все `public` члены базы остаются `public`, `protected` — `protected`.

**3. Что такое виртуальный метод?**
Метод, который можно переопределить в наследнике. Вызов решается во время выполнения (позднее связывание).

**4. Что такое чисто виртуальный метод и абстрактный класс?**
Метод без реализации (`= 0`). Класс с таким методом называется абстрактным, объекты его создавать нельзя.

**5. Почему деструктор базового класса должен быть виртуальным?**
Чтобы при удалении объекта через указатель на базовый класс (`delete basePtr;`) корректно вызывались деструкторы производных классов (иначе будет утечка памяти).

**6. Что такое позднее связывание?**
Определение того, какой именно метод (базовый или переопределённый) вызвать, происходит во время выполнения программы, а не компиляции.

**7. Что такое `override`?**
Спецификатор C++11, который говорит компилятору: «Я переопределяю виртуальный метод базового класса». Помогает избежать опечаток.

**8. Что такое RTTI и `dynamic_cast`?**
RTTI — определение типа во время выполнения. `dynamic_cast` безопасно приводит указатель базового класса к производному (возвращает `nullptr` при ошибке).

**9. Как вызвать метод базового класса?**
Использовать полное имя: `BaseClass::method();`.

**10. Что такое UML?**
Unified Modeling Language — язык графического описания архитектуры ПО (классы, связи).

**11. Что такое паттерн «Стратегия»?**
Инкапсуляция семейства алгоритмов в отдельные классы, позволяющая менять их местами во время выполнения.

**12. Что такое виртуальный деструктор?**
См. вопрос 5.
