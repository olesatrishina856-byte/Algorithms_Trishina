## Теоретическая часть

| Концепция | Описание |
|---|---|
| Алгоритм КМП | Эффективный алгоритм поиска подстроки. Вместо того чтобы при несовпадении сдвигать образец на 1 позицию и начинать сравнение заново (как в наивном алгоритме), КМП использует **префикс-функцию**. |
| Префикс-функция | `pi[i]` — это длина наибольшего собственного префикса строки `s[0..i]`, который одновременно является её суффиксом. Она позволяет при несовпадении сдвинуть образец так, чтобы не потерять уже проверенные совпадения, обеспечивая сложность **O(N + M)**. |
| STL (Standard Template Library) | Набор шаблонных классов (контейнеров) и функций (алгоритмов). `std::set` — это упорядоченное множество уникальных элементов (на основе красно-чёрного дерева, сложность поиска O(log n)). |
| `std::set_intersection` | Алгоритм STL, который находит общие элементы двух *отсортированных* диапазонов и записывает их в результирующий контейнер. |

## Полный код решения

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <set>
#include <algorithm>
#include <iterator>
#include <locale.h>

using namespace std;

// ==================== 1. АЛГОРИТМ КМП (ПЕРВОЕ ВХОЖДЕНИЕ) ====================
vector<int> getPrefix(const string& p) {
    vector<int> pi(p.length(), 0);
    for (int i = 1, j = 0; i < p.length(); i++) {
        while (j > 0 && p[i] != p[j]) j = pi[j - 1];
        if (p[i] == p[j]) j++;
        pi[i] = j;
    }
    return pi;
}

int kmpFirst(const string& text, const string& pattern) {
    if (pattern.empty()) return -1;
    vector<int> pi = getPrefix(pattern);

    for (int i = 0, j = 0; i < text.length(); i++) {
        // Откат по префикс-функции при несовпадении
        while (j > 0 && text[i] != pattern[j]) j = pi[j - 1];
        if (text[i] == pattern[j]) j++;

        // Если дошли до конца образца - нашли первое вхождение
        if (j == pattern.length()) return i - j + 1;
    }
    return -1;
}

// ==================== 2. STL: ПЕРЕСЕЧЕНИЕ МНОЖЕСТВ ====================
void printIntersection(const set<int>& A, const set<int>& B) {
    vector<int> result;
    // Алгоритм set_intersection работает с итераторами
    set_intersection(A.begin(), A.end(), B.begin(), B.end(), back_inserter(result));

    cout << "Результат пересечения: { ";
    for (int x : result) cout << x << " ";
    cout << "}" << endl;
}

// ==================== ГЛАВНАЯ ФУНКЦИЯ ====================
int main() {
    setlocale(LC_ALL, "ru");

    cout << "=== 1. КМП (Поиск первого вхождения) ===" << endl;
    string text = "ababcababa";
    string pattern = "ababa";

    int pos = kmpFirst(text, pattern);
    if (pos != -1) cout << "Первое вхождение образца на позиции: " << pos << endl;
    else cout << "Образец не найден." << endl;

    cout << "\n=== 2. STL: Пересечение множеств ===" << endl;
    set<int> set1 = {1, 2, 3, 4, 5, 6};
    set<int> set2 = {4, 5, 6, 7, 8, 9};

    cout << "Множество 1: { 1 2 3 4 5 6 }" << endl;
    cout << "Множество 2: { 4 5 6 7 8 9 }" << endl;
    printIntersection(set1, set2);

    return 0;
}
```

## Анализ сложности

| Алгоритм | Временная сложность | Память | Обоснование |
|---|---|---|---|
| **Построение префикс-функции** | **O(M)** | O(M) | M — длина образца. Индекс `i` только увеличивается. |
| **Поиск КМП** | **O(N + M)** | O(M) | N — длина текста. Текст проходится один раз без откатов назад. |
| **`set_intersection`** | **O(N1 + N2)** | O(K) | N1, N2 — размеры множеств, K — размер результата. Работает за линейное время, так как множества уже отсортированы. |

## Преимущества и недостатки

**Алгоритм КМП** — гарантирует линейную сложность O(N + M) в худшем случае, что выгодно отличает его от наивного поиска (O(N·M)). Не требует дополнительной памяти, кроме O(M) под префикс-функцию. Основной недостаток — для коротких образцов и простых случаев (например, поиск в тексте без повторяющихся префиксов) накладные расходы на построение префикс-функции могут быть выше, чем у наивного алгоритма или `std::string::find`. Для поиска всех вхождений дополнительно нужен откат `j = pi[j-1]` после каждого совпадения.

**STL (`std::set` + `set_intersection`)** — позволяет писать компактный и читаемый код без ручных циклов, а также гарантирует оптимальную сложность (O(N1 + N2)) благодаря тому, что `set` уже отсортирован. Основной недостаток — `std::set` реализован на красно-чёрном дереве, поэтому операции вставки/поиска стоят O(log n) и требуют больше памяти, чем `unordered_set` (O(1) в среднем, но без гарантии порядка). Для пересечения можно также использовать `unordered_set` — он будет быстрее в среднем (O(N1 + N2) без логарифмического фактора), но результат не будет отсортирован.

**Выбор инструмента** — для поиска подстроки в C++ на практике часто используют `std::string::find` (обычно наивный с оптимизациями, но с хорошей константой), а КМП — когда важна гарантированная линейность (например, при обработке больших текстов или многократном поиске разных образцов в одном тексте). Для работы с множествами STL даёт готовые, проверенные и оптимизированные алгоритмы, что снижает вероятность ошибок.

## Контрольные вопросы

**1. В чём заключается идея алгоритма КМП?**
Не сдвигать индекс текста назад при несовпадении, используя префикс-функцию для сдвига самого образца.

**2. Что такое префикс-функция?**
Массив, где `pi[i]` — длина максимального префикса строки, который совпадает с суффиксом, заканчивающимся на индексе `i`.

**3. Сложность КМП?**
O(N + M). Мы проходим текст один раз (N) и строим префикс-функцию (M).

**4. Как работает восстановление при несовпадении?**
Мы берём значение `pi[j-1]` для текущего индекса образца и сдвигаем образец так, чтобы отбросить заведомо неподходящие позиции, не возвращаясь по тексту.

**5. Преимущество КМП перед наивным?**
Наивный в худшем случае работает за O(N·M) (например, текст "аааааа", образец "аааб"). КМП всегда работает за O(N+M).

**6. Какие контейнеры STL знаете?**
`vector` (массив), `list` (связный список), `set` (множество), `map` (словарь), `stack`, `queue` и др.

**7. Разница `vector` и `list`?**
`vector` — непрерывный массив (быстрый доступ по индексу O(1), медленная вставка в середину). `list` — двусвязный список (быстрая вставка/удаление O(1) по итератору, медленный доступ по индексу O(n)).

**8. Разница `set` и `unordered_set`?**
`set` хранит элементы в отсортированном виде (дерево, O(log n)). `unordered_set` использует хеш-таблицу (порядок не гарантирован, но доступ в среднем O(1)).

**9. Разница `map` и `unordered_map`?**
Аналогично `set`, но для пар «ключ-значение».

**10. Как работают итераторы?**
Это объекты, ведущие себя как указатели. Позволяют перебирать элементы контейнера, скрывая его внутреннюю структуру.

**11. Алгоритмы STL?**
`sort` (сортировка), `find` (поиск), `reverse` (разворот), `set_intersection` (пересечение), `accumulate` (сумма) и др.

**12. Лямбда-выражения?**
Анонимные функции `[](int x) { return x > 0; }`, используемые для передачи условий в алгоритмы STL (например, в `find_if`).

**13. Удаление во время итерации?**
Использовать метод `erase`, который возвращает следующий валидный итератор: `it = container.erase(it);`, иначе итератор станет недействительным.

**14. Идиома erase-remove?**
`container.erase(remove(container.begin(), container.end(), value), container.end());` — правильный способ удаления элементов по значению из вектора.

**15. Как изменить порядок обхода?**
Использовать реверсивные итераторы: `rbegin()` и `rend()`.
